# leads-api — приём заявок с сайта

Небольшой HTTP-сервис на стандартной библиотеке Python: принимает заявки с сайта
`design-processov.ru`, проверяет их и отправляет в Telegram (тема «Задачи»).

## Почему в контейнере

- **Перенос в один шаг**: на новом сервере достаточно `docker compose up -d --build`.
- **Изоляция**: сервис внутри контейнера, система хоста не страдает.
- **Порядок**: зависимости и переменные описаны в файлах, а не «в голове».

## Состав

| Файл | Зачем |
|---|---|
| `Dockerfile` | образ: Python 3.12 slim, код, папка журналов, проверка живости |
| `compose.yml` | как запускать: порт, том для журналов, автоперезапуск, лимит логов |
| `.env.example` | какие переменные нужны, без секретов |
| `leads_api.py` | сам сервис |

## Запуск

```bash
cp .env.example .env      # и заполнить: токен бота, чат, тема, свой id
docker compose up -d --build
docker compose ps         # статус и healthcheck
curl -s localhost:8099/health
```

## Что проверить после запуска

1. `curl localhost:8099/health` → `{"ok": true, ...}`.
2. Заявка с сайта приходит в тему «Задачи».
3. `docker compose logs -f` — в журнале нет ошибок доставки.

## Правила безопасности

- `.env` с настоящим токеном **не коммитим** — только `.env.example`.
- Порт слушает только `127.0.0.1`: наружу выходит через Caddy с HTTPS.
- Журнал не содержит персональных данных: только время, результат, номер сообщения.
